# 声音规则 `@wanwu-v2/sound-rules`

孩子在声音诞生里点的五项（高低、长短、变化、轻响、出现方式）怎样变成听得到的声音，声场和成曲里的背景怎样配合孩子的声音，以及两层怎么混在一起，全由这个包决定。前端预览和以后的后端渲染读的是同一份规则，结果不会对不上。

| 规则文件 | 管什么 | 算法 |
| --- | --- | --- |
| `rules/analysis.v2.json` | 声音体检 | `src/analysis.ts` |
| `rules/shaping.v3.json` | 五个维度 | `src/shaping.ts`、`src/arrange.ts` |
| `rules/background.v1.json` | 本地背景（心情、课本节奏、旋律空档、结尾） | `src/background.ts` |
| `rules/mix.v1.json` | 混音（两层音量、背景让一让、限幅） | `src/mix.ts` |
| `rules/textbook-match.v1.json` | 作品概况（疏密、重复，随 AI 背景请求发送） | `src/textbookMatch.ts` |

- **数值**在 `rules/*.json`。音乐角色只需要改这里，不用碰代码。
- **算法**在 `src/`，都是纯函数：输入采样或体检结果，输出数据。
- **发声**在网页的 `apps/web/src/shared/audio/renderShaped.ts`，它只执行“塑形计划”，本身不带任何数值。
- 全程不用模型、不用联网。原始录音只读，从不改写。

## 两步：先体检，再按卡片塑形

1. **声音体检**（`src/analysis.ts`，规则 `rules/analysis.v2.json`）：每段录音算一次，结果是 `SoundAnalysis`，类型在 `@wanwu-v2/contracts/sound`。
   - **先找单个声音**：先按静音把录音分成一段段；超过 `units.splitAboveSeconds` 的长段，再在明显的音量低谷处（落下又升起 `splitDipDb` 以上）切开。这样鸟群里的一声声鸟叫也能找到。
   - **分三类**（`kind.*`）：
     - **单个声音** `one`：总长不超过 `oneMaxSeconds`，并且只有一声，或者最响的一声比第二响的高出 `oneDominanceDb`。
     - **一串声音** `series`：声与声之间安静的时间占比不低于 `seriesQuietRatio`。
     - **连成一片** `texture`：其余情况。
   - **还会测量**：一声的典型长度（中位数），以及它落在短 / 中 / 长哪一档（`unitLength.*`）；平均响度和峰值；偏高、居中还是偏低（`brightness.*`）。
2. **塑形**（`src/shaping.ts`、`src/arrange.ts`，规则 `rules/shaping.v3.json`）：
   - 纸卡前四问是**描述**孩子当时听到的样子，所以往卡片描述的样子靠：已经在那一档就不动。
   - 第五问“你希望它怎么出现”是孩子的**意愿**，照做。
   - 每一项都作用在**单个声音**上；同一项在三类声音上的做法不同（见下表）。
   - **不在一声的中间一刀切**：只在两声之间切；不得不缩短时用较长的渐弱（`edges.cutFadePortion`）；连成一片的声音前后都留淡入淡出（`edges.textureFadeSeconds`）。

| 维度 | 单个声音 / 一串声音 | 连成一片 | 主要参数 |
| --- | --- | --- | --- |
| 高低 | 原声已在那一档就不动；差一档移 `semitonesPerStep` 个半音（不超过 `maxSemitones`），同时调亮或调暗。只变调，不变长短 | 同左 | `pitch.*` |
| 长短 = **一声有多长（时值）** | 每一声拉长或缩短，每差一档乘或除以 `stretchPerStep`（限制在 `minStretch`–`maxStretch`），音高不变、不剪。每一声仍在原来的时刻出现（不改节奏），拉长后撞上下一声时，下一声才往后让 | 整片放慢或加快（`textureMinStretch`–`textureMaxStretch`），每一声跟着变长或变短 | `duration.*` |
| 变化 | 在**每一声里**往上滑 / 往下落 `contour.unit.bendCents`，同时由闷变亮或由亮变闷；有起伏 = 较快的颤动（`contour.unit.wave`） | 在整段上变化，同时越来越近（`rampDb`）或越来越远；有起伏 = 缓慢的涌动（`contour.texture.wave`） | `contour.*` |
| 轻响 | 先统一响度（`targetRmsDb`、`maxBoostDb`、`peakCeilingDb`），再分三档 `choiceDb`，配合起音快慢和明暗 | 同左 | `level.*`、`intensityTone.*` |
| 出现方式 = **这些声音怎么排** | 出现一次 = 原来的样子。重复 = 最响的那一声按固定节拍出现，排满这一段（至少 `minCount` 次）。一阵一阵 = 声音自己的几声组成一组（`hitsPerGroup`），组与组之间停 `groupGapSeconds`，排满这一段（至少 `minGroups` 组）。慢慢出现 = 一声比一声响（`seriesFromDb`）；单个声音则在这一声里慢慢淡入 | 重复 = 均匀地涌来退去（`waveSeconds`），排满这一段，每一阵取片段里不同的地方；一阵一阵 = 像阵风（`gustSeconds`）；慢慢出现 = 渐强 | `pattern.*` |

**响多久由给它的那一段决定**（2026-10-24）：声场里是孩子剪下的片段，卡片试听是最长 10 秒的试听段。这段的长度乘上长短的拉伸，就是听到的长度；出现方式只决定这段时间里怎么排。所以剪下 45 秒的鸟鸣选「重复」，听到的是约 43 秒的涌来退去，而不是固定 3 次。很短的片段至少重复 `minCount` 次，所以可能比片段长。

**一个声音最多响 `limits.clipMaxSeconds`（45 秒，等于最长的声场）**：超出时在两声之间结束，放不下的整声不要；只有一个声音本身就更长时，才在上限处用较长的渐弱结束。规则校验它不能超过最长的声场。网页据此在声音比声场长时自动换到放得下的长度，并把放不下的长度选项变灰（只看声音本身的长度）。

**选了却没变化时要告诉孩子**：`unchangedBy()` 会判断两种情况。一种是原声本来就是那样（高低、长短落在同一档）；另一种是这个选项本身就是“保持原样”（稳稳的、刚刚好响、出现一次）。声音诞生页会让向导小鸟说出来，例如“它本来就是「短短的」，所以听起来没怎么变”。

**时长**：听到多长由同一条时间线决定（`arrange()`）。它只依据孩子的选择、片段，以及这个声音单元自己带着的体检结果（`SoundUnitDraft.analysis`），所以声场尾条、成曲曲谱和实际渲染一定一致，测试里逐一核对过。声音诞生交出的声音单元、声音库示例都带着体检结果；示例声音的体检结果在生成声音库时算好（`npm run assets:library`）。

在声场里，孩子“剪一剪”出来的片段就是要用的那一段。刚放进声场时，默认是去掉前后静音的整段，孩子再自己剪。

## 本地背景（`background.v1.json`，`src/background.ts`）

成曲里的背景音乐，今天由这份规则在本机生成（降级链路里不联网的“本地动态音符”一档），不用模型。以后 AI 背景接上，失败或超时仍退回这里。

- **输入**：整首的长度（所选长度，或最后一个声音结束，取较晚的）、孩子的声音什么时候在响、心情、选中的课本歌曲（特征模板）、作品 ID（作种子，同一首作品每次一样）。
- **色彩跟心情**（`moods.*`）：每种心情一行——调式 `mode`、主音 `tonic`（也决定音区高低）、和弦进行 `progression`（1–7 级）、旋律疏密 `melodyEveryBeats`（几拍一个音）、重拍力度 `accent`，以及没选课本时的速度 `tempo` 和拍子 `metre`。孩子没选心情时，用课本歌曲的情绪和调式；都没有就是 `none`。

| 心情 | 调式 | 和弦 | 速度 / 拍子 | 旋律 |
| --- | --- | --- | --- | --- |
| 没选 | 大调 | I–vi–IV–V | 76 / 4 | 每拍 |
| 开心 | 大调 | I–V–vi–IV | 100 / 4 | 每拍 |
| 平静 | 大调 | I–IV–I–V | 68 / 4 | 两拍一个 |
| 活泼 | 大调（偏高） | I–IV–V–I | 112 / 2 | 半拍一个 |
| 悲伤 | 小调（偏低） | i–VI–iv–v | 60 / 3 | 两拍一个 |
| 生气 | 小调（低） | i–VI–iv–v | 96 / 4 | 每拍，重拍更重 |
| 害怕 | 小调（低） | i–iv–i–v | 72 / 3 | 两拍一个 |
| 好奇 | 多利亚调式 | i–IV–i–IV | 88 / 3 | 每拍 |

- **节奏跟课本**：选了课本歌曲，就用它的速度、拍子，旋律按它的节奏型 `rhythmCell` 走。心情和课本冲突时，心情管色彩、课本管节奏。只借节奏和气质，不照搬旋律。
- **调式**（`modes.*`）：`scale` 是 7 个音（定和弦），`melody` 是旋律可用的音（五声为主，孩子容易接受）。
- **和弦和低音一直都在**；**旋律只在空档里**：孩子的声音前后各留 `melody.marginSeconds`，空档至少 `melody.minGapBeats` 拍才进来，在音区 `liftSemitones` 起 `rangeSemitones` 之内小步走（每步不超过 `leapSteps`），重拍和乐句最后一个音落在和弦音上。
- **节奏声部**（`rhythm.two/three/four`）：每拍一下，按拍子分强弱；重拍再加 `accentBoost × 心情的 accent`。只有选了小鼓这类乐器才听得到。
- **结尾在长度之内**：主和弦落在离结尾至少 `ending.minRingSeconds` 的最后一条小节线上，延音到结尾；前一小节是属和弦。背景从不让整首变长。
- **淡入淡出**：`fade.inSeconds` / `fade.outSeconds`。
- **声场只有拍点**（`beat`，算法 `beatPlan`）：万物声场选了课本歌曲，听听这段声音只带这首歌的拍子——按它的速度和拍子，每小节第一拍敲 `beat.strong`、其他拍敲 `beat.weak`，用节拍器的嘀嗒声从头敲到尾（强拍高一点、响一点）；`beat.gain` 是拍点这一层的音量。不加和弦、调、特征节奏，也不在孩子的声音下面让一让（拍子要稳，好对着摆）。没选歌就没有拍点，只放孩子的声音。完整的背景只在万物成曲。课本灵感弹窗在声场里的「听一听」也是同一套拍点。
- **谁演奏哪个声部**（`assignParts`）：每件乐器带着“擅长”和“也能演奏”的声部（来自乐器库）。每个声部先给擅长它的乐器，没有就给能演奏的；有音高的声部谁都不能演奏时，保留原始柔和背景。所以不选乐器 = 原始背景，只选小鼓 = 原始背景 + 小鼓。

## 混音（`mix.v1.json`，`src/mix.ts`）

- `childGain`：孩子的声音合在一起的总音量；`backgroundMaxGain`：背景音量条拉满时的音量（0.35：默认音量下背景比孩子“刚刚好响”的声音低约 13 dB，拉满也低约 7 dB，背景不抢自然声音）。两页共用。
- 课本歌曲本身从不进入混音：背景只用它的特征生成音符。
- **背景让一让**（`duck`）：孩子的声音响起时，背景在 `attackSeconds` 内压低 `depthDb`，声音结束后 `releaseSeconds` 内回来；离得很近的几声算一段，不来回抽动。
- **限幅**（`limiter`）：总线上的限幅器，防止两层叠加后爆音。

## 作品概况（`textbook-match.v1.json`，`src/textbookMatch.ts`）

- 孩子的摆放用课本歌曲同样的说法概括：**疏密**（每秒响几声，`density.sparseBelow / busyAbove`）、**重复**（再放一次的声音、选了重复 / 一阵一阵的声音占多少，`repetition.lowBelow / highAbove`）、**高低**、**心情**。只把这几个词随 AI 背景请求发出去。
- 全在本机算，不用模型、不用联网。（「帮我找找」已在 2026-10-30 去掉，匹配用的权重等已删除。）

## 改规则的流程（给音乐角色）

1. 打开 `rules/` 里对应的文件（见最上面的表），改数值。每个数值的含义见各节；允许范围在 `src/schema.ts`（列表写成 `[最小, 最大, 最少几个, 最多几个]`，文字选项列出可选的词）。
2. 运行 `npm test`。填错了（超出范围、拼错名字、短比长还长、轻响三档没有从小到大）会直接报中文错误并指出是哪一项，**不会上到网页**。
3. 用固定的测试声音集逐个维度、逐档听一遍，确认没有把别的声音调坏。

> 遇到问题按现象查对应参数。例如：
> - “一阵一阵太密” → `pattern.bursts.groupGapSeconds`
> - “鸟鸣该算一串声音” → `analysis.kind.seriesQuietRatio` 或 `units.splitDipDb`
> - “长长的不够长” → `duration.stretchPerStep` / `maxStretch`
> - “往上走听不出来” → `contour.unit.bendCents`
> - “悲伤的背景太亮” → `background.moods.sad.mode` / `tonic`
> - “背景旋律太碎、插不进去” → `background.melody.minGapBeats`
> - “孩子的声音一响背景就塌下去” → `mix.duck.depthDb`
> - 改了体检规则（`analysis.v2.json`）后，要运行 `npm run assets:library` 重算示例声音的体检结果，否则检查会报错。

### 调音台（2026-10-24 已做：`/lab/sound-rules`）

**怎么打开**：`npm run dev` 后访问 `http://127.0.0.1:5290/lab/sound-rules`；预览构建用 `VITE_ENABLE_LAB=1 npm run build --workspace=@wanwu-v2/web`。正式构建里没有这个页面（已核对产物里没有它的文件）。

**能做什么**：选一段声音库示例（也就是测试声音集里已有的 8 段）或上传一段；看体检结果（波形上标出主体段和找到的单个声音、分类和预期是否一致、一声多长、高低、响度）；点五个维度和背景心情，试听“原声（统一响度）”“塑形后”“塑形 + 本地背景”；右边四份规则（五个维度、声音体检、本地背景、混音）每个数值一个滑块，范围就是校验范围，播放中拖动会自动重新试听；不合格时列出中文问题、不让导出；合格时“导出…规则文件”，下载的文件名就是规则包里的文件名，放进 `rules/` 即生效。代码在 `apps/web/src/pages/lab/`。

**测试声音集**：清单 `docs/assets/test-set.json`，已有 8 段（声音库示例），还差 11 段待收集（流水、雨、掌声、操场人声、说话、敲门、狗叫、拍手、钟、鸡鸣、安静教室），原件放 `assets-source/audio/test-set/`（见那里的 README）。`npm test` 会核对已有的每一段体检分类是否和预期一致。

以下是原先定下的规则（已照做）：

**它是什么**：给音乐角色用的规则调试工具，用来**定通用规则**，不是给某一段声音单独调。用户（老师、孩子）接触不到它。

**日常使用全部自动**：
- 老师或孩子上传、录音之后，系统自动做声音体检：找出单个声音，分成单个声音 / 一串声音 / 连成一片，统一响度，判断高低。
- 孩子在五个维度上点选，系统按同一套规则自动塑形。
- 整个过程没有人工环节，也不用模型。

**页面要做到**：
1. 只在开发环境（`npm run dev`）或特意开启的预览构建里出现，**正式站不打包**。实现上用动态导入，并由 `import.meta.env.DEV` 或一个预览开关（例如 `VITE_ENABLE_LAB=1`）控制，路由例如 `/lab/sound-rules`。
2. 选一段示例声音、测试声音集里的声音，或上传一段，看到体检结果：主体段在哪、找到的单个声音（画在波形上）、分类、一声多长、偏高 / 居中 / 偏低、响度。
3. 逐个点五个维度的每一档，和原声来回对比。用的就是正式页面的 `planCard` / `planClip` + `renderShaped`，只是把规则对象换成页面上正在调的那份（这些函数都已经接受 `rules` 参数）。
4. 每个参数一个滑块，范围取自 `src/schema.ts`，拖动后马上重渲染并试听。滑块旁边写参数名和 README 里的说明。
5. 一键导出 `analysis.v*.json` / `shaping.v*.json`，导出前先跑同一套范围和关系校验，不合格就不让导出；放进 `rules/` 就生效，不用改其他文件。改了体检规则的，还要运行 `npm run assets:library` 重算示例声音的体检结果。

**测试声音集（回归集）**：
- 上线前准备 15–20 段有代表性的声音：鸟叫、滴水、流水、风、蝉、蛙、人声、敲击、车声、掌声等，三类声音都要有。
- 原件放 `assets-source/audio/test-set/`（不进 `public/`），清单放 `docs/assets/test-set.json`（名称、来源、许可、预期分类）。
- 音乐角色在调音台里用这组声音，把每个维度、每一档都听一遍，调到“大多数声音都合适”，然后导出规则文件。调的是“短短的有多短”“一阵一阵间隔多少”这类通用数值。
- 以后每次改规则，都用同一组声音再听一遍，确认没把别的声音调坏；工作量固定，不随上传数量增加。可以再加一个自动检查：测试集每段的预期分类写进清单，`npm test` 对比体检结果。

**发现问题时怎么定位**：每个参数都有名字，本 README 有对应说明。例如觉得“一阵一阵太密”，就对应 `pattern.bursts.groupGapSeconds`；只改这一个数，页面代码和其他维度都不受影响。

**上线后**：
- 发现某一类声音普遍听着不对，比如很短的敲击声做“长长的”总是怪，就改对应的那条通用规则，所有声音一起生效；听感变了就另存新版本文件。
- 体检认不出声音（整段都是静音或杂音，`SoundAnalysis.silent`），声音诞生页应自动提示“这段好像没录到声音，可以重录”，不需要人工处理。**这条提示还没做**：现在静音录音会被当作原声保留，塑形不出错，但不会提醒。

## 版本

- 规则文件名带版本：`shaping.v3.json`、`analysis.v2.json`、`background.v1.json`、`mix.v1.json`、`textbook-match.v1.json`。上线前的旧草案（`shaping.v2`、`analysis.v1`）没有保存过任何作品，已直接替换。每份文件的 `version` 字段会写进塑形计划和体检结果。
- **上线前**调数值不改版本号，因为还没有保存过的作品。
- **上线后**，任何会改变听感的修改都另存为新版本文件，旧文件保留；作品记录自己用的规则版本，旧作品按原规则重放。这一步在接后端时一起落实。
- 体检结果的类型 `SoundAnalysis` 带有 `rules` 字段。后端可以把它和声源一起保存，体检规则变了再重算。目前网页按缓冲区现算并缓存（`apps/web/src/shared/audio/soundAnalysis.ts`）。

## 已知待调

- 当前数值是草案，只做过数值测量和渲染检查，**还没有用耳机 / 外放实听**。
- 示例里，鸟鸣、蝉鸣、苹果落地、风吹树叶、自行车都被判成“偏高”。这些录音本身高频成分多，分档界线需要用测试声音集来定。
- 峰值很尖的声音（例如滴水），“响亮的”和“刚刚好”音量接近，差别主要来自起音和明暗。整体限幅已放进 `mix.v1.json`。
- 背景的心情表、旋律空档、让位深度、匹配权重都是草案，只做过数值测量（30 种心情 × 乐器组合渲染峰值 ≤ 0.59、有声音时背景低约 6 dB），还没有实听。
- 声音卡试听最长 10 秒。连成一片的长声音（鸟鸣、蝉鸣）在试听里只听前 10 秒左右，在声场里按孩子剪的片段完整播放。
